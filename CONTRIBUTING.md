# Contributing

## Branching

1. Start feature work from `develop`.
2. Use `feature/<module>` for new functionality.
3. Use `fix/<issue>` for defect fixes.
4. Use `release/<version>` and `hotfix/<issue>` only for release management.

## Commits

Use Conventional Commits:

- `feat:`
- `fix:`
- `docs:`
- `refactor:`
- `test:`
- `chore:`
- `ci:`

## Pull Requests

1. Fill in `.github/PULL_REQUEST_TEMPLATE.md`.
2. Include validation evidence for backend and frontend.
3. Document risk and rollback approach for behavior changes.
4. Request review after CI passes.

## Issues

1. Use the bug template for defects or regressions.
2. Use the feature template for new scope or optimization requests.
3. Add acceptance criteria before development starts.
