# 前端与交互设计

## 1. 设计方向

按照 `frontend-design`，本系统选择 **Swiss 管理后台方向**：纯白或中性浅灰表面、清晰网格、左对齐信息层级、一个明确的蓝色主色。原因是终端安全后台需要长期值守、密集阅读、快速定位风险，过度装饰会干扰判断。

差异化动作：所有关键列表采用“状态列 + 风险分 + 最近事件”的固定信息结构，安全人员在不同模块间可以用同一套扫描方式判断优先级。

## 2. UI/UX 质量规则

来自 `ui-ux-pro-max` 的优先级约束：

- 可访问性：文本对比度不低于 4.5:1，图标按钮必须有可访问名称。
- 触控与交互：按钮、筛选项、表格操作最小高度 44px。
- 表单反馈：字段级错误显示在字段附近，提交按钮有 loading 状态。
- 响应式：桌面优先，1366/1440/1920 重点适配；平板单栏详情；移动端保留告警处理和审批。
- 表格体验：支持筛选、排序、列配置、批量操作确认、空态、错误态。
- 动画：仅用于展开、抽屉、状态变化，150-300ms，尊重 reduced-motion。

## 4. 页面结构模板

### 4.1 列表页

适用于终端资产、策略、告警、补丁任务、审计日志。

1. 页面标题区：标题、说明、主操作。
2. 筛选区：关键字、组织、风险等级、状态、时间范围。
3. 批量操作区：选中数量、批量下发、批量导出、批量关闭。
4. 表格区：固定关键列，长文本 tooltip，状态 badge。
5. 分页区：页码、每页条数、总数。
6. 详情抽屉：不离开列表即可查看详情和操作。

### 4.2 策略编辑页

分步表单：

| 步骤 | 内容 | 关键校验 |
|---|---|---|
| 基础信息 | 名称、类型、优先级、说明 | 名称唯一、优先级范围 |
| 目标范围 | 组织、标签、终端动态组 | 必须至少一个目标 |
| 规则配置 | 防病毒、外设、白名单、补丁、隔离规则 | 类型与规则字段匹配 |
| 冲突检测 | 与已有策略比对 | 冲突必须处理 |
| 发布确认 | 灰度比例、发布时间、回滚版本 | 高风险策略需审批 |

### 4.3 告警详情页

采用左主右辅结构：

- 左侧：告警摘要、证据、进程/文件/网络信息、处置时间线。
- 右侧：终端画像、风险分、关联策略、责任人、快捷处置。
- 底部：审计记录、相似告警、附件下载。

## 5. 状态与颜色

| 状态 | 用途 | 视觉规则 |
|---|---|---|
| 低风险/成功 | 在线、已关闭、已合规 | 绿色 + 文本 |
| 中风险/等待 | 待处理、执行中、审批中 | 琥珀色 + 文本 |
| 高风险 | 高危告警、补丁超期 | 红色 + 文本 |
| 严重 | 恶意文件、防护关闭、隔离失败 | 深红底 + 白字 |
| 禁用 | 不可操作、无权限 | 灰色 + disabled 属性 |

颜色不得作为唯一信息表达，必须配合等级文本或状态文案。

## 6. 响应式设计

| 断点 | 布局 |
|---|---|
| `< 768px` | 单栏，保留告警、审批、详情查看核心能力 |
| `768-1199px` | 导航可折叠，表格横向滚动，详情抽屉全屏 |
| `1200-1599px` | 标准后台布局，左侧导航 + 主内容 |
| `>= 1600px` | 增加右侧辅助面板，展示风险画像和待办 |

## 7. 空态、错误态、加载态

- 空态：说明当前没有数据，并给出下一步动作，例如“创建策略”“部署 Agent”。
- 错误态：显示错误原因、traceId、重试按钮。
- 加载态：超过 300ms 显示骨架屏；表格加载保留表头。
- 批量操作：先显示影响范围，再确认执行。

## 8. 可验收 UI 标准

- 所有核心页面首屏必须显示真实模块名和业务字段。
- 表单字段必须有 label，不允许只有 placeholder。
- 表格列宽不应挤压关键状态字段。
- 危险操作必须二次确认。
- 权限不足时隐藏主操作，同时接口返回 403。
- 1366 宽度下不出现主体横向溢出，表格区域除外。
