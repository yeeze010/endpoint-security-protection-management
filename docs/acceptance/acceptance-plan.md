# 验收计划与里程碑

## 1. 验收目标

系统验收以“可部署、可登录、可接入终端、可下发策略、可形成告警闭环、可导出报表、可追溯审计”为核心。验收时必须同时检查功能、数据、权限、安全、性能、文档和运维交付物。

## 2. 验收标准

| 类别 | 标准 |
|---|---|
| 功能 | 核心模块可用，主流程可演示，测试用例通过 |
| 数据 | 终端、策略、告警、工单、审计数据链路完整 |
| 权限 | 不同角色只能访问授权功能和数据范围 |
| 性能 | 10,000 终端规模下核心查询和心跳满足指标 |
| 安全 | 高危漏洞为 0，敏感操作有审计 |
| 文件 | 证据、隔离、补丁、报表文件上传下载正常 |
| 运维 | 可一键部署、可备份恢复、可回滚 |
| 文档 | 需求、架构、设计、API、测试、部署、验收文档齐全 |

## 3. 验收用例

| 编号 | 场景 | 验收动作 | 通过标准 |
|---|---|---|---|
| AC-001 | 登录权限 | 不同角色登录 | 菜单、接口、数据权限正确 |
| AC-002 | 终端接入 | 模拟 Agent 注册和心跳 | 资产列表出现终端且状态更新 |
| AC-003 | 策略下发 | 创建外设策略并发布 | 目标终端收到策略版本 |
| AC-004 | 补丁状态 | 上报补丁缺失 | 风险分和补丁报表更新 |
| AC-005 | 病毒状态 | 上报防护关闭 | 生成高危告警 |
| AC-006 | 外设管控 | 上报 USB 违规事件 | 记录事件、生成告警 |
| AC-007 | 软件白名单 | 上报未授权软件 | 风险因子和告警正确 |
| AC-008 | 风险评分 | 触发重新计算 | 分数、等级、因子明细可解释 |
| AC-009 | 告警闭环 | 派单、处置、复核、关闭 | 状态完整流转，审计可查 |
| AC-010 | 文件附件 | 上传证据并下载 | 文件可访问，权限受控 |
| AC-011 | 报表导出 | 导出合规报表 | 文件生成，内容包含关键指标 |
| AC-012 | 部署恢复 | 重启服务和恢复备份 | 服务恢复且数据不丢失 |

## 4. 里程碑计划

| 里程碑 | 周期 | 交付物 |
|---|---|---|
| M0 立项与范围冻结 | 1 周 | 项目章程、需求范围、验收口径 |
| M1 架构与原型 | 2 周 | 架构图、页面清单、接口清单、数据模型 |
| M2 工程骨架 | 2 周 | 前后端框架、CI、本地启动、基础接口 |
| M3 终端与 Agent | 3 周 | 注册、心跳、资产、软硬件清单 |
| M4 策略与任务 | 3 周 | 策略编辑、审批、下发、执行结果 |
| M5 补丁/病毒/外设/白名单 | 3 周 | 状态采集、规则、违规事件、风险因子 |
| M6 风险与告警闭环 | 3 周 | 风险评分、告警聚合、工单闭环、审计 |
| M7 报表与部署验收 | 2 周 | 报表、部署手册、测试报告、验收材料 |

## 5. 人员分工

| 角色 | 人数 | 职责 |
|---|---:|---|
| 项目经理 | 1 | 计划、风险、范围、验收 |
| 产品经理 | 1 | 需求、原型、验收用例 |
| 架构师 | 1 | 技术选型、架构、代码评审 |
| 前端工程师 | 2 | 管理后台、页面、交互、可视化 |
| 后端工程师 | 3 | API、数据库、策略、告警、审计 |
| Agent 工程师 | 2 | Agent 通信、采集、执行、升级 |
| 测试工程师 | 2 | 测试计划、自动化、性能、安全 |
| DevOps | 1 | Docker、Nginx、CI/CD、监控、备份 |

## 6. 风险与应对

| 风险 | 等级 | 应对 |
|---|---|---|
| Agent 兼容性复杂 | 高 | 建立 OS 兼容矩阵，先做最小闭环，灰度升级 |
| 策略误下发 | 高 | 审批、灰度、影响预览、快速回滚 |
| 告警噪声高 | 中 | 聚合去重、白名单、阈值调优 |
| 性能压力 | 中 | 批量上报、Redis 缓冲、异步处理、压测 |
| 权限越权 | 高 | RBAC + 数据范围，接口级测试 |
| 文件泄露 | 高 | 预签名 URL、过期时间、权限校验、审计 |
