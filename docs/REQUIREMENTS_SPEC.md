# 计算机终端安全防护管理系统需求规格说明

## 1. 文档目标

本文档用于补齐计算机终端安全防护管理系统的业务边界、功能结构、页面清单、角色权限、报表指标与验收范围，作为需求、设计、研发、测试和交付的统一基线。

## 2. 项目定位

- 面向对象：企业安全运营中心、IT 运维团队、终端管理员、审计与内控部门。
- 建设目标：建立终端资产可视、策略可控、告警可闭环、审计可追溯、验收可归档的统一管理平台。
- 当前阶段：`v0.1.0` 演示版，已具备仪表盘、终端资产、策略中心、告警处置、审计日志五个模块的前后端演示闭环。

## 3. 业务范围

### 3.1 核心业务域

1. 组织与账号管理：组织树、用户、角色、权限、登录鉴权。
2. 终端资产管理：Agent 注册、在线状态、风险评分、终端详情、资产归属。
3. 安全策略中心：策略模板、发布审批、灰度下发、冲突检测、版本回滚。
4. 告警与工单闭环：告警聚合、派单、处置、复核、关闭。
5. 审计与报表：操作审计、策略审计、告警闭环统计、合规与补丁指标。

### 3.2 非本期范围

1. 真正的终端杀毒引擎与内核驱动。
2. 高级威胁检测模型训练平台。
3. 多租户计费、商业结算、外部客户门户。

## 5. 业务流程

### 5.1 终端纳管流程

1. 运维安装 Agent 并注册终端。
2. 平台记录终端基础信息、组织归属和在线状态。
3. Agent 定期心跳与事件上报，平台更新风险评分。
4. 管理员在终端台账查看在线情况、风险等级和处置入口。

### 5.2 策略发布流程

1. 安全管理员创建策略草稿。
2. 平台执行规则校验与冲突检测。
3. 审批人完成审核。
4. 平台按组织、终端组或标签灰度发布。
5. Agent 增量拉取最新策略。
6. 平台跟踪执行结果并支持回滚。

### 5.3 告警闭环流程

1. Agent 或规则引擎上报告警。
2. 平台聚合重复告警并生成事件。
3. 安全管理员研判并创建或关联工单。
4. 执行人处置并补充证据。
5. 复核人确认结果后关闭工单。
6. 全流程写入审计日志并纳入报表。

## 7. 数据模型范围

当前迁移脚本已定义以下核心实体：

- `organizations`
- `users`
- `endpoints`
- `policies`
- `security_alerts`
- `incident_tickets`
- `audit_logs`

补充约束如下：

1. 用户必须关联组织，可选关联角色集。
2. 终端必须具备唯一 `agent_id`，按组织归属统计。
3. 策略必须保留版本号、状态和审批信息。
4. 告警必须关联终端，工单必须关联告警。
5. 审计日志必须记录操作人、资源类型、资源标识和结构化详情。

## 10. 报表与指标定义

| 指标 | 口径 | 刷新频率 | 用途 |
|---|---|---|---|
| 终端总数 | 已纳管终端数 | 5 分钟 | 资产规模 |
| 在线率 | 在线终端数 / 总终端数 | 5 分钟 | 运维健康度 |
| 高危告警数 | 严重和高风险未关闭告警数 | 1 分钟 | 安全态势 |
| 补丁合规率 | 已安装关键补丁终端数 / 需安装终端数 | 日 | 合规指标 |
| 告警闭环时长 | 从告警产生到工单关闭的平均时长 | 小时 | 处置效率 |
| 审计覆盖率 | 关键操作带审计记录的比例 | 日 | 审计完整性 |

## 11. 非功能要求

1. 登录接口响应时间目标小于 2 秒。
2. 首页总览接口在 1 万终端规模下目标小于 3 秒。
3. 审计日志必须支持至少 180 天留存。
4. 关键配置变更必须保留可追溯日志。
5. Docker 环境需支持单机演示部署。

## 12. 版本验收范围

### 12.1 `v0.1.0` 演示版

1. 五个页面可访问。
2. 后端演示接口全部可返回结构化数据。
3. 本地脚本可完成启动与基础健康检查。
4. Docker 编排文件结构齐备。

### 12.2 `v0.3.0` 目标

1. 接入真实数据库。
2. 完成基本 RBAC。
3. 补齐策略发布和告警工单动作。
4. 增加后端单元测试与前端类型校验流水线。
