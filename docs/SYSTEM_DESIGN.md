# 终端安全防护管理平台概要设计

## 1. 设计目标

1. 建立可演示、可扩展、可验收的前后端分层架构。
2. 支撑终端资产、安全策略、告警处置和审计追踪的主链路。
3. 以低耦合方式为后续接入 PostgreSQL、Redis、MinIO、认证授权和报表模块预留扩展点。

## 2. 总体架构

### 2.1 当前架构分层

- 前端：Vue 3 + TypeScript + Vite，负责管理端页面和 API 调用。
- 后端：Spring Boot 3 + Java 21，提供 REST API 与演示数据。
- 数据层：Flyway 迁移脚本已定义核心表结构，当前运行态接口仍使用内存示例数据。
- 部署层：Docker Compose 编排 PostgreSQL、Redis、MinIO、后端、前端和 Nginx。
- 交付层：GitHub Actions 执行后端测试、前端构建和交付物校验。

### 2.2 目标逻辑组件

| 组件 | 职责 | 当前状态 |
|---|---|---|
| Auth 模块 | 登录、令牌、权限上下文 | 演示态 |
| Dashboard 模块 | 聚合平台指标 | 已有演示 |
| Endpoint 模块 | 资产台账、详情、状态同步 | 已有只读演示 |
| Policy 模块 | 策略查询、发布、回滚 | 已有列表演示 |
| Alert 模块 | 告警查询、研判、派单 | 已有列表演示 |
| Audit 模块 | 审计记录查询与导出 | 已有只读演示 |
| Report 模块 | 报表聚合与导出 | 待建设 |

## 3. 后端设计

### 3.1 包结构

当前后端按照业务域拆分包：

- `auth`
- `dashboard`
- `endpoint`
- `policy`
- `alert`
- `audit`
- `api`
- `config`

建议下一阶段补齐：

- `service` 层，承载业务规则。
- `repository` 层，对接数据库。
- `security` 层，承载 JWT、认证、鉴权和拦截器。
- `report` 层，承载报表聚合逻辑。

### 3.2 API 返回规范

所有接口统一通过 `ApiResponse<T>` 返回，要求包含：

1. `success` 布尔值。
2. `message` 说明。
3. `data` 业务数据。
4. `traceId` 或等价字段，便于问题排查。

### 3.3 数据持久化演进方案

1. 保留现有 Flyway 脚本作为数据库基线。
2. 引入 Spring Data JPA 或 MyBatis Plus 管理实体与查询。
3. 使用 PostgreSQL 承载主数据，Redis 承载会话和热点缓存。
4. 使用 MinIO 存储告警证据、导出文件和附件。

### 4.1 页面路由

当前路由：

- `/audit`

- `/login`
- `/reports`
- `/users`
- `/roles`
- `/policies/:id`
- `/alerts/:id`

### 4.2 前端状态策略

当前项目结构较轻，数据通过页面级请求拉取。后续建议：

1. 在需要共享用户、菜单、筛选条件时引入 Pinia。
2. 将 API、数据模型、错误处理统一收敛到 `src/api.ts` 与独立模块。
3. 建立通用列表页模式：筛选区、指标摘要、表格、详情抽屉、空态和错误态。

## 5. 数据设计摘要

### 5.1 关键实体关系

1. 一个组织包含多个用户与终端。
2. 一个终端可对应多条安全告警。
3. 一条告警可衍生一条或多条工单。
4. 一条策略由创建人创建、审批人审批，并按版本演进。
5. 审计日志可记录任意资源对象的变更行为。

### 5.2 数据一致性要求

1. 终端删除默认采用逻辑删除或停用，不直接物理删除。
2. 策略发布后必须保留历史版本，不覆盖旧版本。
3. 工单关闭时需要同步更新告警状态。
4. 审计日志为附加写入，不允许业务覆盖。

## 6. 权限设计

### 6.1 菜单权限

当前演示登录接口返回以下菜单权限：

- `dashboard`
- `endpoints`
- `policies`
- `alerts`
- `audit`

### 6.2 按钮级权限规划

| 模块 | 动作 |
|---|---|
| 终端资产 | 导出、隔离、解除隔离、补丁下发 |
| 策略中心 | 新建、编辑、审批、发布、回滚 |
| 告警处置 | 指派、忽略、转工单、关闭 |
| 审计日志 | 查询、导出 |

## 7. 部署设计

### 7.1 本地开发

使用 `scripts/start-local.ps1` 自动完成：

1. 检测 JDK 21。
2. 准备 Maven。
3. 构建并启动后端。
4. 安装依赖并构建前端。
5. 启动前端并验证 API 代理。

### 7.2 Docker 演示环境

通过 `infra/docker-compose.yml` 启动：

1. `postgres`
2. `redis`
3. `minio`
4. `backend`
5. `frontend`
6. `nginx`

### 7.3 生产化待补事项

1. 将明文默认密码改为环境变量注入。
2. 为 PostgreSQL、Redis、MinIO 增加持久化与备份策略。
3. 接入日志采集、指标监控与告警。
4. 补齐 HTTPS、访问控制和最小权限配置。

## 8. 测试设计

1. 后端：单元测试、控制器集成测试、Flyway 迁移验证。
2. 前端：类型检查、组件渲染测试、关键页面冒烟测试。
3. 端到端：登录、列表访问、详情查询、告警闭环主流程。
4. 交付物：文档、图示、脚本、Docker 配置完整性校验。

## 9. 风险与技术债

1. 当前接口以演示数据为主，尚未与数据库实体打通。
2. 登录接口返回固定令牌，尚未提供真实认证与会话控制。
3. 前端未接入自动化测试框架。
4. CI 仅做构建与文档存在性检查，尚未做部署预演和安全扫描。
